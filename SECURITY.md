# Security

## Verifying Binaries

All release binaries are built in public via GitHub Actions. Each release has a `SHA512SUMS` file with the SHA-512 checksum of every binary in it. Releases before 2026.06.29 have a `.sha512sum` file next to each binary instead.

Before using a downloaded binary, download `SHA512SUMS` from the same release and verify the binary:

```bash
# On Linux / macOS, in the folder with the binary and SHA512SUMS
sha512sum -c SHA512SUMS --ignore-missing
```

```powershell
# On Windows (PowerShell): the two hashes must match (Get-FileHash prints upper case)
Get-FileHash clang-format-22_windows-amd64.exe -Algorithm SHA512
Select-String clang-format-22_windows-amd64.exe SHA512SUMS
```

The checksums in each release are generated by CI from the same build that produced the binaries — there is no manual upload step.

## Trusting the Supply Chain

If you prefer not to trust pre-built binaries, you have two options:

1. **Build from source yourself** — Use `python build.py` (see [README](README.md#building-locally)) to reproduce any build on your own machine.
2. **Fork and run CI** — Fork this repository and run the GitHub Actions workflow on your own fork. The binaries you download from your fork’s releases page were produced by your own CI.

## Reporting a Vulnerability

If you discover a vulnerability in a binary or in the build process, please report it privately via GitHub Security Advisories:

👉 **[Report a security vulnerability](https://github.com/cpp-linter/clang-tools-static-binaries/security/advisories/new)**

Do not open a public issue. We treat reports seriously and will respond as quickly as possible.

## Scope

This repository does not write or maintain the clang tools themselves — it only builds them from upstream LLVM source. If you find a bug in clang-format, clang-tidy, etc., report it to [LLVM](https://github.com/llvm/llvm-project/issues).
